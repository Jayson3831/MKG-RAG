## 2. 统一证据口径

### 2.1 固定评测边界

每次运行声明语言、release、各源 dump 日期、抽取配置、文件及 SHA-256、ontology 版本、参考映射版本、评测图范围、关系白名单、查询模板及推理规则。相同 release 不等于内容来自同一时刻。

优先使用语言独立、保留局部实体标识的文件；核查是否存在跨语言融合或统一 URI。QID 和 interlanguage links 建立评测用参考映射，不从外部知识库补充答案事实。所有跨图推导保留来源。

局部邻域可用于发现候选。单图必要性复核必须在声明的完整评测图内进行；若只加载主题子图，结论只适用于该主题子图，不能宣称完整 DBpedia 单图不可回答。抽样遗漏、查询超时和检索失败均不算已证实缺失。

### 2.2 答案与必要性

先固定正向查询语义。设联合证据下经过核验的完整答案集合为 A*，各单图答案为 A_en、A_fr。A* 必须非空且证据有效，不要求只有一个答案。

- 严格跨图连接：联合查询能完成推导，A_en 与 A_fr 均为空；需核验桥接映射和替代路径。
- 集合补全：各单图都不能给出完整 A*，但至少一个单图能给出部分答案；与严格跨图连接分开统计。
- 单图可回答：至少一个单图足以完整支持 A*。
- 证据不足：联合后仍无足够证据；只能标记当前范围内不足，不能把缺失当作否定事实。
- 冲突/无效：映射错误、事实冲突或抽取错误使参考答案不能确定，先单列复核。

除执行原查询外，按预先声明的规则复核等价谓词、逆关系、直接关系及其他允许的替代证据路径。不能只证明某一条选中路径跨图，就认为问题必须跨图；也不声称穷尽未声明的自然语言推理。

### 2.3 标准化与误差审计

- 保留原始三元组、来源图及标准化对应关系。
- 共享 ontology 属性使用完整 URI；本地属性必须通过显式语义映射处理，不能删除语言前缀后直接合并。
- 对象实体仅在参考映射可信时映射为同一实体；未对齐项单列，不能全算成独有事实。报告映射覆盖率，并抽查错配与多对一映射。
- 日期保留精度；数值统一兼容单位并记录转换，容差由属性配置确定。
- 文本保留语言标签和原文；跨语言文本等价无法确认时标记未知，不自动计为互补或重复。
- labels、abstracts、comments 和 sameAs 不计入答案事实重合率；标签可用于检索，同一条件下各系统权限一致。
- 差异分类为重复、有效互补、时间差异、粒度差异、冲突、抽取/映射错误或待核验。同一属性多个不同值不自动视为冲突。

## 3. E002：第二轮——在线框架可用性

### 3.1 前置条件与对照任务

使用 E001 冻结的、来源与参考答案已核验的数据。保留严格连接、集合补全、单图可回答和证据不足子集，分别报告结果；冲突任务在有可靠冲突标注后单独加入。

主划分按跨语言实体等价类分组；记录桥接实体和邻域重叠。另设模板泛化划分，规模允许后再做图谱/时间泛化。保持问题语言固定以隔离图谱语言影响；问题语言变化作为后续独立变量。

### 3.2 基线与映射条件

| 条件 | 用途 |
|---|---|
| 各单图独立系统 | 检查单图基线；逐题最佳单图仅作诊断上界 |
| 参考映射 + 确定性联合查询 | 数据层面的可回答上限，不计为 Agent 成绩 |
| 参考映射 + 相同 GraphRAG 执行器 | 估计移除实体对齐难度后的系统上限 |
| 全图广播检索 | 衡量来源选择的必要性及额外成本 |
| 离线对齐后合并图 | 与在线局部对齐比较；记录离线成本和查询摊销假设 |
| 部分映射可见 + 在线对齐 | 评估已有链接不完整时的表现 |
| 测试实体映射不可见 + 在线对齐 | 评估未提供测试跨图映射时的局部发现能力 |
| Oracle source selection | 在有多个候选图时隔离选图误差 |

部分映射可见率、随机种子、候选检索范围和测试桥是否隐藏均写入配置。评测参考映射与系统资源隔离，检查 QID、sameAs、统一 URI、索引、缓存和 Graph Card 是否泄漏答案或映射。保留合法的本地标签/别名/结构线索，不把正常实体名称信号算作泄漏。

各系统使用相同模型、问题、数据快照和资源权限；控制或报告工具预算、检索预算、缓存状态及索引构建成本。Oracle 独有信息明确标注。

### 3.3 分阶段执行

1. **双图连接实验**：固定 en/fr，先验证映射精度、连接正确率、证据与答案，避免将选图复杂度混入第一步。
2. **映射可见性消融**：改变可见映射比例，定位错误来自实体匹配、关系理解还是图内推理。
3. **多候选图实验**：扩展到至少三个候选图，加入相关及无关来源，在混合可回答性任务上测试选图、继续检索、停止与拒答。该阶段落实 E003。
4. **Schema 扩展**：在 mapping-based 基础上增加经审计的本地 infobox 属性，单独验证关系映射，落实 E004；不把共享 Schema 上的成功外推到复杂异构 Schema。

可增加移除正确桥接候选、实体别名歧义、来源冲突等受控诊断；这些人工干预必须单独标识，不计入自然互补发生率。

### 3.4 评估与错误归因

- 答案：实体/值标准化后的 EM/F1，按必要性子集、模板及实体层次报告。
- 证据：路径有效率、来源可追溯性、证据召回和跨图 Join 正确率；允许经核验的替代正确路径，不能只匹配单一参考路径。
- 对齐：Precision/Recall/F1，说明候选范围和覆盖不足。
- 决策：必要来源召回、不必要图谱访问、提前停止、拒答及其校准。
- 成本：Token、工具调用、访问图数、延迟、离线准备成本；在相近质量或同预算下比较。多组合法来源集合时，依据有效证据评估选图，不强制唯一来源集合。

错误标签：源选择、实体候选缺失、错配、关系语义错误、局部检索遗漏、连接错误、替代路径漏检、时间/冲突处理、答案生成和不当拒答。保留失败案例及原始运行证据。

若模型不稳定，按预先记录的种子重复运行，并做配对比较；数据已满足 E001 但系统表现差时，优先诊断系统，不立即淘汰图谱。

### 3.5 可支持的结论

- 正确映射下有可回答增益：支持数据的跨图价值。
- 隐藏测试映射后仍能有效对齐并回答：支持在线局部对齐能力。
- 多候选图下保持质量并降低不必要访问：支持选图与成本优势。
- 与离线合并对比成立时，明确在线/离线成本的摊销条件。
- 双图 mapping-based 实验不能单独证明自治异源图、复杂 Schema 对齐或冲突处理能力。

## 4. 每次运行的记录与产物

运行目录：`outputs/runs/<YYYYMMDD-HHMMSS>_<experiment-id>/`。建议保存：

```text
manifest.json        输入文件、SHA-256、版本、时间与环境
config.json          实际配置、抽样/映射权限及随机种子
command.txt          可复现命令
run.log              日志与失败信息
metrics.json         指标、分母和不确定性
queries.jsonl        查询、单图/联合结果与替代路径检查
certificates.jsonl   答案、来源、桥接映射与证据范围
audit.jsonl          人工审计与错误标签
figures/             图表（如有）
```

证据证书至少包括 question_id、模板/自然语言问题、参考答案、required_graphs、bridge_mappings、来源三元组、single_graph_results、necessity_type、评测范围配置引用、替代路径检查状态和冲突状态。仅在最小性已验证时称为“最小证据”；否则标记为候选证据集。

运行中的执行状态、失败、方案偏离、实际命令及待审核信息保存在运行目录的 `run-status.json` 与日志中；任务书仅维护任务要求、版本和交接状态。实验完成并审核后，将可行性分析写入 [实验验证记录](validation-log.md)，包括实验/运行编号、结论、关键指标及分母、证据链接、原因分析和适用边界。证据不足时如实说明尚不能判定，不能强行归为不可行。

实验验证记录不保存运行流水账、待执行任务、验证方法或空白结果模板。

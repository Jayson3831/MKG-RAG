## 1. 待验证假设

H1：语言图间存在经语义标准化和质量核验后仍成立的互补事实。

H2：这些事实能形成跨实体、跨模板的自然跨图连接问题，且无法由任一单图中的允许替代路径完成。

## 2. 数据与抽样

1. 核查 en/fr 同一 release 的 mapping-based objects/literals、instance types、labels 和跨语言映射文件，冻结输入清单。具体 release 待核查后填写。
2. 初步计划抽取约 1,000 个共享实体，按人物、作品、组织、地点及连接度分层；记录随机种子、各层规模、抽样概率和映射覆盖率。稀缺类别报告实际数量。
3. 对目标关系读取完整出边，按两跳/三跳模板补全所需邻域，保留连接到的语言特有实体。不设置每实体“前 20～50 条”的截断。
4. 共享实体样本用于桥接分析；实体总体重合率应另用完整实体清单或独立总体样本计算，不能在已筛选的共享实体上估计总体重合。
5. 将评测用对齐视图与原图分开存储；运行时权限设计留到 E002。

## 3. 两条候选采样轨道

**轨道 A：发生率估计。** 事先固定实体分层、两跳/三跳查询模板、抽样分布与候选去重规则，生成候选时不要求跨图。明确这是给定采样分布下的发生率，不能外推为自然用户问题分布。模板频次和分层权重随配置保存。

**轨道 B：可构造样本挖掘。** 专门搜索跨图路径，记录尝试数、合格数、失败原因、实体与模板覆盖。该轨道衡量构造效率与样本产量，不估计天然发生率。

两个轨道均先生成结构化查询、答案及来源，再验证单图/联合可回答性，最后为合格样本生成自然语言问题。改写后检查问题是否保留原查询的约束与语义。

结构示意（不是已发现实例）：

```text
G_en: 作品 A → 导演 B
G_fr: 导演 B′ → 出生地 C
参考映射: B ≡ B′
问题: 作品 A 的导演出生在哪里？
```

除顺序连接外，可探索两个图上的条件交集；集合补全另设子集。比较、排序等任务在明确完整性边界后再扩展，第一轮不引入缺失即否定的查询。

## 4. 执行顺序

1. 输入审计与映射抽查，建立来源可追溯的标准化事实视图。
2. 计算实体、Schema、事实重合与差异类别，记录无法比较的比例。
3. 按轨道 A/B 分别生成候选及参考查询。
4. 执行 en、fr 和联合查询，在完整评测范围复核允许的替代路径。
5. 分类严格连接、集合补全、单图可回答、证据不足和冲突/无效；失败和超时单列，不作为不可回答证明。
6. 对合格候选分层随机抽查约 100 条（不足则全查），核查来源事实、桥接实体、语义、替代路径和时间一致性；另抽查失败案例解释误差。定向排错样本不能并入随机质量估计。
7. 输出证据证书、数据划分建议与进入第二轮的决策。

## 5. 指标

| 指标 | 口径与限制 |
|---|---|
| 实体 Jaccard / 对齐覆盖率 | 基于完整清单或独立总体样本；未映射项单列 |
| Schema 重合 | 共享 ontology 与本地属性分别报告；名称相似不代表语义等价 |
| 事实 Jaccard、各图独有事实比例 | 在可比较且已对齐范围计算，给出分母；按实体宏平均与总体微平均分别报告 |
| 有效互补比例 | 排除已确认噪声，并将时间、粒度、冲突和未知项单列 |
| 必要问题发生率 | 仅轨道 A；分别统计严格连接和集合补全 |
| 合格产量及挖掘通过率 | 仅轨道 B；合格数/尝试数，不称天然必要率 |
| 质量与多样性 | 人工通过率、实体/桥接实体/模板分布、长尾覆盖与重复率 |

轨道 A 的主分母为预先采样且语法/类型有效的全部候选，包含联合证据不足的候选：

```text
R_strict = 严格跨图连接候选数 / 全部有效候选数
R_completion = 集合补全候选数 / 全部有效候选数
R_multi = R_strict + R_completion
```

另报告“联合可回答候选中的必要率”，明确其条件分母。保留原始抽样总数、无效数及未完成核验数；尚未核验的样本不得默认为负例。出现超时或未决项时报告覆盖率与上下界，待复核完成再给最终点估计。

重复实体/模板造成样本相关性时，置信区间采用分层或按实体聚类的估计；不把高度重复的问题当成独立证据。

## 6. 决策规则

- 继续 E002：能获得质量可核验、实体与模板足够多样的真实跨图问题，并能形成避免实体泄漏的独立评测划分。
- 扩展采样：数量或覆盖不足，但已确认有真实互补；先检查样本偏差、映射覆盖与抽取覆盖，再决定扩语言或领域。
- 定位为辅助实验：差异主要来自文本、噪声或少数模板，或任务主要依赖既有统一 Schema/显式映射。
- 切换主数据：经过上述审计仍缺少足以支持框架论证的问题，再考虑近同构或异源图。

不设“Jaccard 高则淘汰”规则；正式 benchmark 所需规模和质量阈值应在扩规模前明确并记录，不能看见系统结果后反向挑阈值。

### 默认运行规模与协议冻结

- 种子默认 `42`；实体目标约 1,000 个，按本任务书第 2 节分层，保存完整抽样清单。实体不足时报告实际覆盖。
- 轨道 A 默认抽取 1,000 个去重后的候选，保留不足目标、拒绝采样及无效候选数量。语法/类型有效但联合答案为空的候选仍保留。
- 轨道 B 默认最多尝试 5,000 个候选构造；每次尝试及失败均登记。尝试如何计数、重复如何处理在运行前固定，达到上限即结束，报告实际产量。

- 人工审计目标为合格候选中的分层随机 100 条，不足则全选；另准备最多 20 条失败或高风险样本，用于诊断而不混入质量估计。
- coding agent 根据本机资源与源文件元数据，先在配置中记录下载字节预算、磁盘/内存上限、执行时限及估算。资源不足时可以缩小明确的主题评测范围并说明影响，不得默默截断出边或降低必要性复核覆盖。
- release、文件清单、范围、模板、采样规则、推理规则和预算须在正式统计前冻结并计算配置哈希。先做的小规模开发运行标注为探索；数据驱动调模板后使用新运行编号，并明确结论基于该模板分布，不作为无偏的全领域发生率。
- 遇到不可用文件、解析完整性失败或预算耗尽，保留运行证据并交付“部分完成/阻塞及原因”；不能以演示数据冒充真实验证。无需为了未达到目标数量无限扩展下载或采样。

### 实现中的关键判定约束

1. **输入完整性**：记录每个文件实际读入的三元组数、重复数和解析错误数。损坏或未完成的输入不能支撑其覆盖范围内的“事实不存在”结论。不可获取的源 dump 日期或配置标为未知，不能猜测补齐。
2. **局部身份**：单图查询的起点实体须通过相同参考映射解析为该图的本地实体；允许评测器为比较结果做身份归一化，但单图事实只能来自该图。不得因使用另一语言的 URI 导致空结果并误判必要性。
3. **公平事实范围**：单图与联合查询使用相同白名单、语义和标准化规则；联合图的事实只能来自已声明两图，映射只连接身份。所有输出答案可追溯到输入三元组；来源独有判定需要确认该语义事实在另一图的完整评测范围不存在。
4. **桥接要求**：严格连接证书须展示有效的跨图实体桥及来自两图的答案推导。若实体桥歧义或证据缺失，标为未决；映射边不计为答案事实。
5. **替代路径**：预先定义可执行的等价/逆关系与直接关系重写、允许的图内路径及最大深度，保存规则依据。若未实现某类检查，写明范围限制并标记未完成项，不能以空白字段声称已排除所有路径。结论只覆盖实现且完整执行的规则集。
6. **候选账本**：每个候选都有固定 ID、轨道、模板、种子/抽样位置、根实体、桥接实体（如有）、判定状态和原因。语法错误与类型不合法的排除条件在查询前定义；查询返回空不能转记为“无效”。
7. **分类与计数**：对有效候选使用互斥状态 `strict_join`、`completion`、`single_graph`、`insufficient`、`conflict_invalid`、`unresolved`。映射、事实或冲突问题在语法/类型有效后发现时，保留在主分母中并单列；其多图必要性视为未知，未决上下界应包含这些样本。A* 非空且各单图结果均为空才可计入 `strict_join`。
8. **等价答案**：保存未归一化和归一化答案，记录允许的替代推导。发现单图答案不属于联合答案时，应触发一致性错误并复核，不继续发布必要率。
9. **事实质量**：自动判定的互补候选与人工确认的互补区分开。无法自动核验的语义或时间问题标为待审计；不能将 coding agent/LLM 自评标记成“人工通过”。
10. **数据划分**：给出跨语言实体等价类分组的可行性检查，报告根实体、桥接实体、模板集中度及拟定划分的重叠。单纯更换问题措辞不计入模板多样性。

### 最小接口与交付文件

建议入口为 `scripts/run_e001.py`，可复用逻辑放 `src/`，冻结配置放 `configs/e001.yaml`，依赖声明和锁定文件放工程适当位置。接口可按实际技术栈调整，但必须提供以下等价能力及实际可执行命令：

```text
prepare       获取并核验数据、建立派生视图，支持缓存复用
run           按冻结配置执行两个轨道，创建新运行目录
recompute     只读取已保存候选/查询/审计记录，重算指标
verify        按指定 question_id 从源事实独立复核证据和可回答性
audit-export  用指定种子导出随机审核包及独立诊断包
```

`verify` 不得只比较缓存标签或调用同一判定函数返回成功；至少使用独立的简单查询执行路径或原始三元组解释器重新求解，并输出实际答案和原始证据。它可以共享 RDF 解析器和已核验的语义规则；仍需通过人工原始证据抽查防止共同错误。

除 [实验验证计划](../experiments/validation-plan.md) 第 4 节的运行产物外，E001 必须补充：

| 文件 | 内容 |
|---|---|
| `candidates.jsonl` | A/B 轨道完整候选账本，含无效、重复与未决记录 |
| `sampling.json` | 实体样本、模板分布、权重、种子、尝试预算及各阶段计数 |
| `normalization.jsonl` | 事实标准化和桥接映射的原始依据，可用可寻址派生文件引用代替重复数据 |
| `audit-selection.json` | 冻结的审核样本 ID、选择方法、种子、所属层及抽样概率 |
| `audit-samples.html` | 可离线打开的审核表：原始三元组、源文件定位、桥接依据、问题/查询、三种答案、替代路径检查及勾选项 |
| `checks.json` | 完整性、计数一致性、复算、独立重放和正确性测试结果 |

HTML 是本次运行的审核产物，放在运行目录，不另建平行的总结文档。源定位可采用源文件哈希加未压缩行号，或其他可独立检索的稳定定位；不要仅提供可能已更新的在线实体页面。

`audit.jsonl` 中分别保存 `auto_status`、`human_status`、`reviewer`、时间、证据问题和备注。初始人工状态必须为 `pending`；人工实际审核后才填写通过或不通过。发现问题后保留原标签和修订标签，不能覆盖原始判定记录。

### 必须覆盖的正确性测试

使用明确标记的微型合成图做单元测试，不混入真实实验统计。至少覆盖：

- 两图各提供一段路径、各单图为空，联合完成答案的严格连接；
- 单图存在另一条允许的直接/逆关系路径，应归为单图可回答；
- 两图提供不同答案子集，应归为集合补全；
- 跨语言本地 URI 不同但身份相同，单图起点应正确解析；
- 标签翻译、单位等价与日期精度差异不会被机械计为有效互补；
- 映射歧义、查询超时、损坏输入不会被判成已证实缺失；
- A/B 分母、重复候选和未决上下界正确；空分母输出 `null`/不适用，不能输出 0% 造成误导；
- 加入单图替代证据后，严格连接标签必须改变；删除一条选中路径但仍有另一条合法路径时，答案仍成立。

### 交付时的结果摘要格式

在运行目录保存完整交付信息，至少包括下列内容；经审核的可行性分析及必要证据摘要写入 [实验验证记录](../experiments/validation-log.md)，不把命令清单、执行过程或待审核状态复制过去：

1. 范围：release、输入快照及实际加载范围，运行/配置/代码标识；未建 Git 时保存源代码哈希清单。
2. 规模：各图实体/事实数、映射覆盖、实际抽样数、模板数、A/B 尝试及各类数量。
3. 结果：事实差异各类比例、轨道 A 必要率及区间/未决界限、轨道 B 合格产量、分层多样性。
4. 质量：自动检查、独立重放结果、人工已审/待审数量及抽样通过率；不能以自动结果代填人工质量。
5. 例证：各至少一个真实严格连接、单图替代路径、集合补全及失败/未决样本（不存在时明确写未发现），附 ID 和证据链接。
6. 判断：进入 E002 / 补采样 / 辅助实验 / 当前数据不支持 / 证据不足，并说明范围及依据。
7. 复现：环境准备、运行、指标重算、指定样本复核与审核包打开方式的实际命令。

交付前在运行目录的 `run-status.json` 记录 `工程验收：待审/通过/未通过` 与 `研究审核：待人工/支持继续/需补证据/不支持`，不要把两者合并成一个“成功”。如尚无人审计，coding agent 的任务可交付为“实现与运行完成，研究判断待人工审核”。

## 8. 验收与用户审核指南

### 第一关：判断实验是否做对

先看五项硬条件，任一失败即退回修复，暂不讨论数据是否适合框架：

| 硬条件 | 审核方法 | 不通过的典型信号 |
|---|---|---|
| 输入可追溯且范围完整 | 核对 manifest、SHA-256、加载计数、解析错误、范围配置 | 混版本、文件不完整、出边截断却声称单图缺失 |
| 候选分母可对账 | 从账本重算 A/B 数量；检查每个排除原因 | 只交付成功案例、把空答案/超时删掉、把 B 当天然率 |
| 指标可复算 | 执行交付的 recompute 命令，对比计数、分母和输出 | 报告与逐样本结果对不上，未决项被当成负例 |
| 样本可独立重放 | 随机选样本执行 verify，比较三种答案和来源 | 只复述证书标签，没有实际查询或原始事实 |
| 结论与实际检查一致 | 查配置中的推理范围、替代路径检查和人工状态 | 检查未执行却声明“无其他路径”，自动审计被写成人工 |

可复算检查须计数完全一致；浮点区间允许配置声明的数值容差。自检通过不足以替代人工审计。

### 第二关：你逐条审核哪些内容

先用交付后的另一个固定种子（例如 `20260911`）从冻结账本重新抽样，保存选择结果，避免仅查看 coding agent 挑出的漂亮案例。仍按层抽样，并保留相应权重。第一次可先看 20 条严格连接候选做快速排错；最终质量审核完成目标 100 条或全部合格候选。快速排错样本若不是正式随机样本，不混入正式通过率。

每条在审核表检查以下六项：

1. **事实确实存在**：英文和法文每条关键三元组都能在固定输入文件找到；结构化事实与问题含义一致。若检查现实事实，区分“忠实于快照”与“现实正确”，遇到疑点记录为质量问题。
2. **桥接确实同一实体**：检查参考链接、标签、类型及邻居，排除同名不同人、不同版本作品、组织分支与总部混配。
3. **答案确实由联合证据推出**：按关系逐跳阅读，核对方向、日期精度、单位及限定条件；不依赖模型常识补齐缺失关系。
4. **单图确实无法完成**：检查单图起点已经解析为本地 URI，查看单图查询和替代路径的实际输出。重点尝试找一条单图捷径；无法肉眼证明所有缺失时依赖完整查询记录，并核对其规则范围。
5. **任务没有被人为造难**：两图保留原始事实，独有判定不是截断、隐藏事实或缩窄单图检索权限造成的；评测主题范围在结论中明确。
6. **分类与自然语言一致**：全部单图为空才是严格连接；部分答案属于集合补全；至少一个单图完整回答则为单图可回答。自然语言问题与结构化查询约束一致。

任一关键项不通过，该样本不能作为已验证的跨图必要证据。记录原因并让 coding agent 检查同类样本，修复后重新运行相关流水线；不要只删除被抽查发现的坏样本后宣布总体合格。

另外独立审计最多 20 条失败/高风险样本，重点找“本来可回答却被漏掉”和“映射错误产生的假互补”；诊断结论单列。正式质量率按原分层抽样权重计算，同时报告原始通过数、样本数和区间。未审核的样本保持待审核。

### 第三关：判断研究上值不值得继续

工程验收通过后，再依据人工质量及数据分布作决定：

- **支持继续 E002**：存在经核验的真实跨图问题，覆盖多类关系/实体；桥接实体和模板分布允许独立评测，不只集中在几个高频实体；报告的构造产量和范围足以支持计划中的下一轮。
- **需要补证据**：正确样本存在，但人工审核未完成、未决比例大、替代路径范围窄或样本/模板不足。明确补哪一项，维持结论待定。
- **作为辅助实验**：有效问题主要集中于少数模式，或只能支持共享 Schema 下的实体对齐，难以覆盖拟验证能力。
- **当前数据不支持**：完整、可复现的审计后仍缺乏真实互补问题，或差异主要来自噪声。结论限定当前 release、范围、模板及预算，不外推为所有多语言图不可用。

不要求某个预设的 Jaccard 或 R_multi 数值才能验收，也不以“发现 100 个问题”自动证明整体框架可行。E001 只验证数据与问题的基础；E002 才检验系统能力。正式扩规模前需冻结所需样本规模、质量及泛化标准。

用户审核过程、工程状态和逐条意见保存在运行目录。审核后的可行性分析写入 [实验验证记录](../experiments/validation-log.md)：结论、支持或反对的证据、错误类型及原因、适用范围；证据不足时说明无法判定的原因。有效结论同步更新《研究思路》的主方案；否定或替代过程只写其独立记录章节。
